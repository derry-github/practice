## 一、 实践考核任务说明
本次实践任务要求使用 C++ 语言，通过纯指针方式实现一个链表模型（不使用 STL 库）。具体功能包括：
1. 实现链表的动态生成（支持空格分隔、回车结束）；
2. 实现向链表中增加新节点的功能；
3. 实现正向删除第 N 个节点及反向删除第 N 个节点的功能；
4. 能够正确管理内存并返回头节点状态。

## 二、 算法设计与分析

### 2.1 数据结构设计
本程序采用了**带头结点的双向循环链表**：
- **Node 类**：包含 `int data`、`Node* prev`（前驱指针）和 `Node* next`（后继指针）。
- **哨兵头结点 (Sentinel Node)**：不存储实际数据，作为链表的起始和结束标识，简化了边界条件的判断（无需判断 `head` 是否为空）。

### 2.2 核心算法逻辑
1. **尾插法 (add)**：由于是循环链表，`head->prev` 始终指向最后一个节点。插入新节点时，只需修改 4 个指针指向即可在 $O(1)$ 时间内完成。
2. **通用删除方法 (remove)**：
   - **定位**：根据方向（正/反），从 `head` 出发沿 `next` 或 `prev` 移动 $N$ 步到达目标节点。
   - **删除**：利用双向指针，执行 `curr->prev->next = curr->next` 和 `curr->next->prev = curr->prev`，随后释放内存。
3. **输入处理**：利用 `cin.peek()` 和 `cin.ignore()` 识别回车符，实现了灵活的空格分隔输入。

## 五、 实践总结与心得
通过本次实践，我深入理解了复杂链表结构的优势：
1. **结构优势**：双向循环链表通过增加一个前驱指针和哨兵节点，极大地简化了代码逻辑。尤其是反向删除，在单链表中需要 $O(n)$ 寻找前驱，而在双向链表中与正向删除同样高效。
2. **逻辑完备性**：哨兵结点的应用展示了如何通过牺牲极少量的空间（一个空节点）来换取代码的健壮性和简洁性。
3. **交互优化**：在编写 `create` 方法时，通过对输入流的细致控制，提升了程序在 CLI 环境下的用户体验。
