二、实践原理：
1、C++ 语言特性应用：
   - 封装性：定义 `PageManager` 类，将物理块数组（blocks）、容量（capacity）、缺页统计（faultCount）等数据成员封装在类内，通过公共接口（access, isHit）暴露功能。
   - 初始化：利用构造函数对物理块进行统一初始化（-1 表示空闲），确保对象建立时的状态正确。
   - 资源控制：利用类成员维护 FIFO 算法的“先进”状态指针（nextReplace），实现逻辑自洽。

四、实践步骤：
1. **类结构声明**：定义 `PageManager` 类。使用私有数组 `int blocks[5]` 限制最大物理块，并声明 `capacity` 和 `nextReplace` 变量。
2. **逻辑封装**：实现 `isHit(int page)` 私有方法，通过循环遍历 blocks 数组判断页面是否存在。
3. **置换核心实现**：在 `access(int page)` 方法中，若发生缺页且内存已满，根据 `nextReplace` 索引进行覆盖，随后执行 `nextReplace = (nextReplace + 1) % capacity` 实现循环队列逻辑。
4. **主函数交互**：
   - 使用 `cin.clear()` 处理输入流异常，确保物理块数输入的健壮性。
   - 利用 `cin.peek()` 检测换行符，实现动态长度的页面序列读取。
5. **结果计算**：通过 `(float)faultCount / total` 强制类型转换，配合 `setprecision` 得到精确的缺页率百分比。


五、数据记录：
1. 实验设置：物理块容量 = 3。
2. 访问序列：4 3 2 1 4 3 5 4 3 2 1 5。
3. 关键节点记录：
   - 访问 4, 3, 2：物理块由空变为 [4][3][2]，均发生缺页。
   - 访问 1：置换 4（最早进入），块状态为 [1][3][2]。
   - 访问 4：置换 3，块状态为 [1][4][2]。

七、实践结论：
通过本次实践，深刻体会到了 C++ 类在处理复杂系统状态（如内存管理）时的优势。FIFO 算法虽然逻辑直观且易于利用循环指针实现，但在实际应用中需注意其对页面重要性的忽略，本次实践为后续研究 LRU 等更高级算法奠定了面向对象的程序基础。


八、注意事项：
1. **构造函数初始化**：必须确保所有物理块初始值为 -1 或非法值，防止干扰命中判断。                              
2. **类型转换**：计算缺页率时，分子或分母需强转为 float，否则会产生整数截断误差。                              
3. **循环边界**：`nextReplace` 的自增必须与 `capacity` 取模，防止数组越界。
